Promotion Version Comparator (June 2026, uncommitted on develop). Components in `dpm/src/components/promotions/version-comparator/`: `VersionComparator.tsx`, `fold-audit-logs.ts`, `json-prune.ts` (pickPaths), `PromotionPicker.tsx`, `types.ts`. Mock is DELETED (no mock-data.ts).

**Real BE wired** via `getAuditChain`/`getAuditPromotions` in `dpm/src/app/actions/promotion-actions.ts`. Endpoint: `GET {PROMOTION_MANAGEMENT_BASE_URL}/api/v1/auditLog` — header **`requestorigin: DCM-UI`** + `Authorization: Bearer <session.access_token>` (NOT X-Authoring). Per-promotion fetch uses `?entityId=<promotionId>`; the list (picker) fetches with no param and groups client-side by `entityId`. Response = `AuditLogEntry[]`, each entry one version transition carrying **full `before`/`after` snapshots**, `deltas`, `version{major,minor}`, and actor in **`modifiedParty.id`** (NOT `changedBy`). `lifecycleStatusChange` optional.

Two routes: `/promotions/compare` (picker — sidebar entry "Version Comparator", type `versioncomparator`) → `/promotions/compare/[id]` (the comparator). Compare page derives header from chain's latest `after` snapshot (no getPromotion → no 404). BreadcrumbLink is a plain `<a>` so basePath must be hardcoded: `/promotion-manager/promotions/${id}`.

Comparator UI: from/to version dropdowns labeled **Before/After** (no synthetic pre-v1.0 entry — base v1.0 → first edit v1.1); three views via toggle — **Before & After** (side-by-side JSON via @uiw/react-json-view + lightTheme, "Changed fields/Full document" sub-toggle), **Changed only** (delta section accordions; Criteria renders rich before/after via reused `CriteriaPreview` in `CriteriaCompare.tsx` driven by `buildCriteriaPreviewArray` in `criteria-preview-data.ts` + master data from `getMasterData()`/`loadCriteriaVariables()`; criteria version dropdown picks net or a specific vX→vY; falls back to delta rows when no master data), **Audit Trail** (numbered STEPPER w/ Added/Removed/Modified per version). NO tabs, NO change-summary/impact panel. Sections mirror EDIT SCREEN sheets: Details/Criteria/Organize/Valid For/Limits/Translations/Coupons/Status (`sectionForField`). Friendly names via `FIELD_LABELS` + leaf fallback. Criteria sub-field deltas collapsed into one rule per criterion (`collapseCriteria`). from/to/view persisted in URL query. Dates `suppressHydrationWarning`. DEBUG logs REMOVED. Picker (`PromotionPicker`) has search + client pagination (10/page) + lifecycle status + relative time; `getAuditPromotions(fetchLimit=500)` groups by entityId. Pagination is windowed (client-side over the fetched rows) — server-side paging not done.

**Coupon support (June 2026) — SINGLE page, home-style toggle:** ONE sidebar entry "Version Comparator" → `/promotions/compare`. That page clones the home design: renders the home `PromotionTypeToggle` (flips `?type=promotion|coupon` on the same path) and fetches `getAuditPromotions(filters, type)`. NO separate coupon routes/sidebar entry (an earlier two-route version was reverted; `ComparatorTypeToggle` was deleted). `getAuditPromotions(filters, kind, fetchLimit)` takes kind `"promotion"|"coupon"|"all"`: differentiates SERVER-SIDE via `&entityType=CouponPromotion` / `&entityType=Promotion` (the only two entityType values) on the auditLog URL, plus a snapshot `isCouponPromotion` safety filter on the grouped result. Detail route `/promotions/compare/[id]` serves BOTH; it detects coupon via `isCouponPromotion(latestDoc)` to deep-link the breadcrumb to `/promotion-manager/{couponpromotions|promotions}/${id}`. `PromotionPicker` has a `compareBasePath` prop (default `/promotions/compare`) and was rewritten to use the shared `DataTable` (TanStack) + `StatusBadge` to match the promotions-list table; row click uses `navigateForward`.

**Audit filters (June 2026):** picker reuses `FilterSelects` whole (rendered as `filterSlot` next to the picker search). `getAuditPromotions` appends filters to the auditLog URL using BOTH `before.*` AND `after.*` prefixes (audit JSON nests promotion under before/after) — e.g. `&before.lifecycleStatus=Draft&after.lifecycleStatus=Draft`, dates use `validFor.startDateTime>=` / `validFor.endDateTime<=`. First-load defaults brand/channel to permission scope (mirrors list page). `getAuditChain` normalizes any incoming id (strips `AUDITLOG-` prefix + version suffix) and queries `entityId=${code}-1.0`. versionOptions deduped by key; labels read "Version 1.0"; "Changed only" tab renamed "Attribute Compare". A temporary `console.warn` remains in `getAuditChain` (remove after BE QA).
