The "Fableland" 3D amusement park (Next.js 15 + React Three Fiber + Rapier) is a standalone app at `C:\Users\malliar\Desktop\amusement-park` — the user explicitly wanted it on the Desktop, not inside the promotion-management repo, and confirmed Desktop is fine (it is not OneDrive-synced). Built June 11, 2026.

**Why:** Two `next dev` instances in the same folder crash each other with `EPERM: .next\trace` — the user tends to run `npm run dev` in their own terminal in parallel.

**How to apply:** Before starting any dev server for this app, check `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` for command lines matching `amusement-park` and stop stale ones (the user's other long-running node servers must NOT be touched). Install with `npm install --legacy-peer-deps` (leva peer range lags React 19). Ports 3000/3001 are usually taken by the user's other servers.

**Models / assets:** The Ready Player Me CDN (`models.readyplayer.me`) and likely other non-GitHub CDNs are **DNS-blocked on this network** — fetching realistic avatars from there fails with "remote name could not be resolved". GitHub raw IS reachable: 3D model GLBs come from `raw.githubusercontent.com` (three.js examples Soldier/Xbot, Khronos glTF-Sample-Assets CesiumMan, readyplayerme/animation-library). Player avatar is currently CesiumMan (textured human). Crowd is CesiumMan clones. Shooting-gallery ducks use the classic Khronos **Duck.glb** (118KB, from `glTF-Sample-Models/main/2.0/Duck/...`) in `public/models/`. NOTE: low-poly game-prop CDNs (poly.pizza, Quaternius, KayKit) are BLOCKED/404 on this network; only `raw.githubusercontent.com` works, and Khronos sample PBR objects there are heavy (5-10MB). No free gun model was reachable — shooting rifle stays procedural. To add more real props the user must drop a `.glb` into `public/models/` themselves.

**Verification:** `playwright-core` is installed; headless checks live in `scripts/check-*.js` driving `msedge`. The dev build exposes `window.__park = { store, rig, shooting, look }` for teleport/state tests. Ride boarding does NOT use rapier sensors (they never fired for the player body) — it's a per-frame AABB check; same for the ticket booth and the game-stall proximity (distance check in each stall's useFrame).

**Player + crowd are both CesiumMan** skinned clones (SkeletonUtils.clone) over the rapier capsule — `components/Player/PlayerAvatar.tsx` and `components/world/Crowd.tsx` (per-clone material tint for clothing variety, walk clip, distance LOD, count by quality). Only one realistic model is reachable (CDN blocked) so all share one face. `FairCrowd.tsx` (queues/stall spectators) is still the stylized instanced people.
